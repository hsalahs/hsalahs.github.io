# Infrastructure, deployment and test environment

_Moved out of CLAUDE.md (nothing was removed). Read this when: before deploying, changing branch protection, security headers / GitHub Pages limits, running live checks from the sandbox, the Firebase CLI / plugin, or the live walkthrough test account._

- **`main` is now branch-protected** (classic rule, user set it up): requires a PR + both the "Page tests (Playwright)" and "Firestore security rules (emulator)" status checks to pass before merging. No required-approvals rule (the user is the only account, so self-approval would be impossible).
- **Live walkthrough (done, Oct 2026):** with the test account `claude-check@da3wt.com` (password given to the user in chat — never commit it; the user may keep it for future checks or delete it), event `0quri7ji2z` "حفل تخرج تجريبي" (graduation, 2 test guests, one VIP). Verified on real Firebase: sign-up, login, graduation event → sapphire theme, automatic link `da3wt.com/hfl-tkhrj-tjreebi`, add guest, VIP via the sheet, guest opens the readable link (invite shows, URL stays readable, splash switches to the graduation kind). The door scanner was tested by the user on their phone (works). How to run it from this sandbox: Chromium's proxy drops requests, so serve the repo's files from disk under the da3wt.com origin (`ctx.route`), CDN libraries from curl'd copies, launch with `--disable-http2 --disable-quic`, and retry; Firestore's Listen/Write channels still drop often.
- **Security headers on GitHub Pages:** custom headers (HSTS, X-Frame-Options, CSP frame-ancestors) are impossible on GitHub Pages and `frame-ancestors` is ignored in a meta tag. Decided: no Cloudflare in front for now (DNS change, low benefit — HTTPS is already enforced). Instead app/event/scan.html carry an inline frame-buster at the top of `<head>` (hide + break out). `robots.txt` disallows app/event/scan/invite and points to `sitemap.xml` (index + guide only). A third-party audit's "dev notes visible on the homepage" turned out to be real for plain-text readers: they keep `<script>` contents (but drop HTML comments), so the splash script's `//` comments were the first words of index.html. Then a second audit (VibeQuality) read the raw source and flagged the HTML comments too, so index.html now carries **no comments at all** (HTML, CSS, script) — a landing test guards it; explain index.html changes in commits/CLAUDE.md instead. The splash hider lives in `<head>`. Its removed notes, for reference: no `<link rel="manifest">` on purpose (Add to Home Screen would save app.html's start_url); the sample card's date is refreshed to three weeks from today by the bottom script (format.js, Western digits) and its title rotates through event kinds.
- **Sandbox note:** this environment's Chromium reaches the internet through a flaky proxy (random `ERR_TOO_MANY_RETRIES` on gstatic/fonts), so live end-to-end timing runs here are unreliable; curl is fine. A probe left one Firebase Auth account `test-probe-1791062200803@da3wt.com` (no Firestore data) — the user can delete it in the Console.
- **Firebase plugin (Oct 2026):** `.claude/settings.json` registers the official `firebase/agent-skills` marketplace and enables `firebase@firebase` for this project (no tokens or secrets in the file). Signing in to the Firebase CLI is done per session with `npx firebase-tools login --no-localhost` (the credentials live in the user's config folder outside the repo, never commit them); use it read-only (rules, usage) unless the user asks otherwise — the rules are still published by the user by hand.
