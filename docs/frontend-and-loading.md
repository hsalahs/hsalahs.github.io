# Frontend, loading speed, fonts, splash, icons, phones and browsers

_Moved out of CLAUDE.md (nothing was removed). Read this when: before touching page loading, fonts, splash screens, icons, layout on phones, old Android / iOS Safari behaviour, saving invitation cards, SEO / share cards, or the mobile audit rules._

- **Icons + font (user-approved "version 2"):** buttons, menus and headings use inline Lucide line icons (`icons.js`: `ICON_PATHS`, `ic(name,size)`, and `<i data-ic="name" data-size="n">` filled by `fillIcons()` on load) — never emoji there; messages/toasts keep emoji. event.html's ☰ menu is grouped (الضيوف / الدعوات والتقارير / المناسبة, then guide + red "خروج"), each item an icon in a `.chip`. Icon-only buttons carry `aria-label` (tests use `getByRole('button', { name: 'القائمة' })` for ☰). Body font is IBM Plex Sans Arabic everywhere (canvas cards too); Reem Kufi stays for brand titles. New icons: copy the inner SVG from lucide-static into `ICON_PATHS`. sw.js precaches icons.js (scan.html needs it offline).
- **Speed batch 1 (Oct 2026):** (1) invite.html loads `firebase-init-lite.js` (app + Firestore only, same config/persistent cache/pagehide-pageshow reload/`_isFirestoreTerminated`/`_db`/`_fsFns` keys and `appDbReady`; `_fsFns` holds only what invite uses: collection, onSnapshot, doc, setDoc, getDoc) — it never loads the auth SDK. Don't switch invite back to `firebase-init.js`; if invite starts using another Firestore function, add it to the lite file's import and `_fsFns`. The stubs work unchanged (they match the CDN urls). sw.js precache is unchanged (scan.html only; `CACHE_NAME` bumped to v9). (2) The QR library (qrcodejs) is no longer a blocking script on invite.html: `loadQrLib()` injects it only when an approved card is drawn, waits up to 2s for `window.QRCode` after load, and a failure shows "تعذّر تجهيز البطاقة..." with tap-to-retry instead of a blank card. (3) `<link rel="preconnect" href="https://firestore.googleapis.com">` on invite/scan/app/event.html (no other preconnects added). (4) sw.js network-first timeout 3000 -> 1500 ms. (5) index.html removes the `#splash` node after it hides (hide time and fade changed later, see Splash batch) so its infinite animations stop; index.html still carries no comments, so this note lives here.
- **Splash batch (Oct 2026):** the design and animations are untouched; only the fixed waiting went. index.html hides the splash when the window `load` event has fired AND ≥1600 ms passed since it started (the 1.4 s rings entrance completes), hard cap 3000 ms; fade 0.4 s (was 0.8 s), node removed 500 ms later. invite.html hides when the event data arrived (`window._splashDataAt`, set at the top of `showInviteKind`, or at once for `?demo=1`) AND ≥1600 ms since start AND ≥1.2 s after the kind faded in (`_splashKindAt`), cap 3500 ms (also when the data never arrives); same 0.4 s fade. index.html: the page content between nav and footer is now inside `<main>`, `.section-title` is an `<h2>` (with `font-weight:400`), the feature cards' titles are `<h3>` (were h4), so headings go h1 → h2 → h3 with no skips and no visible change. Contrast of index.html text (WCAG, reported, not changed): the footer text `#6f6a62` on `#0A0A0A` is 3.69:1, and the sample card's `.cp-title` `#C9A84C` 2.29:1, `.cp-date` `#999` 2.73:1, `.cp-id` `#B0AAA0` 2.21:1 on `#FAFAF8` are below 4.5:1; everything else is above 5:1 (`#8a857a` 5.39).
- **Local fonts (Oct 2026):** no page loads Google Fonts any more (it was a render-blocking stylesheet, about 2.5 s of first paint on the landing page). The woff2 files live in `fonts/` (IBM Plex Sans Arabic 400/500/700 arabic+latin, Reem Kufi 700 arabic+latin, Playfair Display 700 latin; named `family-weight-subset.woff2`, about 235 KB in all, fetched from the Google CSS with a Chrome user agent so the unicode-range blocks match). The identical `@font-face` block (font-display:swap, same family names) sits inline at the top of every page's `<style>` (index, invite, app, event, scan, guide), so there is no extra request; `tests/fonts.spec.js` fails if any page's block differs. To add a weight or subset: download the woff2, check it starts with `wOF2`, add the line to all six pages, and to sw.js SHELL_FILES if scan.html uses it. Don't re-add the Google `<link>` or the fonts.googleapis/gstatic preconnects. Preload: index and invite preload IBM Plex Sans Arabic 400 arabic and Reem Kufi 700 arabic (body text and the splash title); the other pages don't (max 2 per page). scan.html is offline-capable, so sw.js precaches all nine files (`CACHE_NAME` v11). The attendance report (a separate window) declares IBM Plex 400/700 from `origin + /fonts/...` and its CSP allows `font-src` for that origin only.
- **Invite layout shift (Oct 2026):** invite.html's card had a 230 px loading line that became about 640 px when the event arrived (centred in the body, so the whole card jumped; CLS about 0.083 in the test, 0.263 measured by PageSpeed with the font swap). Now `#card` starts as `.card-wait` (`min-height:600px`), released by a MutationObserver when `#loading` is replaced. The card is also the page's `<main>` landmark (`<main class="card" id="card">`, no layout change). `tests/invite-cls.spec.js` measures CLS with a delayed event for each kind and asserts under 0.1 (now about 0.01).
- **Organizer splash kind (Oct 2026):** event.html's splash shows the event's kind logo like invite.html (same markup, CSS and `icons/kind-*.svg`). An inline script paints the kind stored in `localStorage ev_kind_<eventId>` (neutral logo when absent); `showEventKind(type)` fades the right one in when the event doc loads and stores it. app.html's `renderEvents` writes `ev_kind_<id>` for every listed event (no extra reads), so the first "فتح" is already right. The 2200 ms hide script is unchanged and independent: never make this splash wait for data.
- **Cross-tab auth (Oct 2026):** Firebase sign-in is shared by every tab of one browser. scan.html's lockDevice ("تسجيل خروج من هذا الجهاز") still signs out any identity but no longer calls `warmIdentity()` afterwards (it used to sign in anonymously and turn an organizer's other tab into an anonymous user; the warm-up when the code gate first shows stays, and checkPin's `ensureIdentity` signs in on tap). event.html: once the dashboard has started (`dashboardStarted`), an auth change to no user / anonymous sets `sessionEnded`, hides `#dashboard`, shows "انتهت جلسة الدخول على هذا المتصفح — اضغط هنا لتسجيل الدخول" (link to app.html) and keeps the red connection banner hidden (`refreshConnectionBanner`); no listeners restart, and if the owner/admin comes back the page does `location.reload()`. No rules change.
- **Save card buttons (Oct 2026):** both the organizer's per-guest card button (event.html `downloadGuestCard`) and the guest's "حفظ الدعوة" (invite.html `downloadInviteCard`) open the phone's share sheet when it can take files (WhatsApp shows up there with the ready invitation message as the caption next to the image; to keep the image the user picks "save image"/Photos), and only fall back to a download when it can't. We tried saving directly on Android (a `prefersDirectSave()` helper) and the founder rolled it back: it downloaded the image but lost the WhatsApp share with the message. Don't re-add it unless asked. `tests/save-card.spec.js` guards the share sheet on Android, an Android in-app browser, iPhone and desktop on both pages, and the download fallback.
- **iOS Safari kills Firestore on `pagehide`:** the SDK (10.12.0) stops its client for good on Safari when the page is hidden; if the page comes back (back-forward cache, tab returning) every call fails with "The client has already been terminated". `firebase-init.js` reloads the page on `pageshow` (persisted) / visible-after-pagehide, and `window._isFirestoreTerminated(e)` lets error handlers (event.html `showErr`, scan.html check-in) reload instead of alerting. Found in the user's live walkthrough.
- **Stuck-loading safety net + busy buttons (from a programmer friend's iPhone test):** app.html and event.html turn a still-plain "جاري التحميل..." into tap-to-retry after 12s (`STUCK_LOADING_MS`) — his new event saved fine but the dashboard took ~90s to open. `setButtonBusy()` (utils.js) disables login/signup/create-event buttons with a ⏳ label while working; the auth and create-event fields are real `<form>`s so the phone keyboard's Go key submits. Next agreed step: replace emoji used as button/heading icons with an inline SVG icon set (Lucide), show a before/after mockup first; keep emoji inside messages.
- **Root cause of the iPhone slow/stuck loading (found in the SDK source, 10.12.0):** `getAuth()` installs the popup/redirect resolver, and on any mobile/Safari/iOS browser (`_shouldInitProactively`) auth initialization *awaits* it — loading apis.google.com + a cross-origin iframe from wedding-qr-16d01.firebaseapp.com — before `onAuthStateChanged` ever fires, on every page load. firebase-init.js now uses `initializeAuth` with getAuth's exact persistence list (indexedDB, localStorage, sessionStorage) and NO resolver; the site never uses popup/redirect sign-in. Don't switch back to `getAuth()`. Measured in an emulated iPhone (Chromium): before — login form never appeared within 40s; after — same as desktop. Also: the EmailJS and JSZip CDN scripts are now `async` (as plain scripts they blocked the whole page, sign-in included, until their CDN answered); `notifyAdmin` initialises EmailJS on first use.
- **Script load-failure bar:** app/event/invite/scan.html have a tiny inline `<head>` listener (capture-phase `error` on same-origin `<script>` elements): if one of the page's own files fails to download, a red fixed bar "⚠️ ما اكتمل تحميل الصفحة بسبب ضعف الإنترنت — اضغط هنا لإعادة التحميل" (`#load-fail`) reloads the page. Found in the live walkthrough (format.js dropped → dashboard half-built, no invite link; utils.js dropped → login button dead). CDN scripts are deliberately not watched (the tests block them).
- **Mobile audit (Oct 2026):** every page checked at 320/375/430 px with long names/emails/links (viewport meta on all pages; menus, forms, sheet, admin panel opened). Only two problems: a long email pushed the admin's account row (and event card) past the screen — fixed with `min-width:0` + `overflow-wrap:anywhere` in app.html; a long event name ran under scan.html's pinned refresh button — fixed with side padding on `h1`. `tests/mobile.spec.js` guards both (no sideways scroll at 320/375 on 9 screens). Known and accepted: at 320 px the guest rows squeeze long names (the three action buttons take the room); fine at 375.
- **SEO / share cards (Oct 2026):** checked against a 7-point SEO list — index.html was already complete; guide.html got a description, canonical and OG/Twitter card. invite.html and 404.html (readable links) carry a generic share card "لديك دعوة خاصة 💌" + og-image.jpg so a shared invitation isn't a bare link; it can't name the event (static files, no server to render per-event tags), Tested by the user in WhatsApp: the guide's card shows; a readable link (`da3wt.com/<slug>`, served by 404.html with HTTP 404) shows **no** card — WhatsApp skips 404 pages. Decided (user): keep the readable link as is, no card (the name in the link is enough); a per-event card with the readable link would need a server. Private pages stay disallowed in robots.txt, so their SEO doesn't matter.
