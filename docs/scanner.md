# Door scanner (scan.html) and check-in

_Moved out of CLAUDE.md (nothing was removed). Read this when: before any work on scan.html, door check-in, the result overlay, door code / door supervisors, the names list ("عرض الأسماء"), check-in by name, concurrency, or scanner speed on old phones._

- **Door supervisors** ("مشرف الباب"): open the scan link and type a 6-digit door code; the anonymous session lives in `events/{id}/scanSessions`. Wording: "مشرفين", never "فريق الأمن".

Don't remove the warm-up. (2) qr-scanner 1.4.2 is vendored at `vendor/qr-scanner.umd.min.js` (no more unpkg; precached in sw.js, `CACHE_NAME` v10) and updated by hand. - **Scan result overlay (Oct 2026):** scan.html shows each check-in result in ONE full-screen `#result-overlay` (fixed, z-index 100001, above splash/banner/load-fail; end of body, `role="alert"`), replacing the three old result cards (ids `#result-allowed/-duplicate/-denied/-vip-ok` are gone; tests use `#result-overlay.rs-allowed|rs-duplicate|rs-denied|rs-error`, `#result-name`, `#result-vip`). Tweak colours and sizes in the `--res-*` variables on `#result-overlay` (CSS: `--res-ok/-dup/-denied/-error`, `--res-icon`, `--res-name`, ...); durations, texts, beep tones and vibration patterns in the `RESULT_UI` constant at the top of the script (allowed 5000 ms, duplicate/denied 6000 ms — the founder found 1.5 s and 3 s too fast at the door; a tap closes sooner; error stays until tap). `showResult(kind, name, vip, message)` / `hideResult(instant)`: one timer; taps in the first 400 ms (`tapGuardMs`) are ignored; while it is up `scanCooldown` stays true; on hide `scanCooldown=false`, camera-status back to 'وجّه الكاميرا نحو الباركود', and `lastScanned` is cleared 600 ms AFTER hide (`clearLastMs`) so the card still in front of the camera isn't shown as 'used'. `hideResult(true)` (instant) is used by handleScan start, resetScanState, sessionRevoked, lockOrClose, lockDevice (no delayed reset). The camera keeps running behind it. Sounds: allowed one short 1000 Hz beep, duplicate/denied low double buzz, error one long low tone; vibrate 80 / [150,80,150] / 300 / 300 (guarded, iOS ignores). An error (failed check-in write) now shows the overlay and waits for a tap (the old code freed the scanner at once). icons.js gained `alert`. sw.js `CACHE_NAME` v13. **Late-result guard:** a module `scanEpoch` is bumped in resetScanState, sessionRevoked, lockDevice and lockOrClose; handleScan captures it after its own hideResult(true) and, if it changed when the transaction settles, skips showResult, the camera-status text and the permission-denied/reload handling (the guests-list/offline-cache bookkeeping still runs); `showResult` is also a no-op while `#scanner-view` is display:none. **Sound on iOS:** `unlockAudio()` creates one shared AudioContext and resumes it (promise ignored, try/catch) on the 'تشغيل الكاميرا' tap (`startCamera`) and the 'تحقق' tap (`submitManualCode`), and `playBeep` calls it again before every tone; no AudioContext = silent, never throws. The guide describes the auto-close times.
- **Scanner button per role (Oct 2026):** scan.html's `#lock-device-btn` decides its label in `showScanner()`: door-code devices (`usesSessionDoc` true) keep "تسجيل خروج من هذا الجهاز" (`lockDevice()`, unchanged); the organizer or admin (opened automatically or via the admin form, `usesSessionDoc` false) sees "إغلاق الماسح" (icon `x`, matching aria-label) and `lockOrClose()` only stops the camera/watchers and goes to `event.html?id=<eventId>` — no signOut, no session-doc delete, because sign-in is shared with the organizer's other tabs; an anonymous or signed-out user falls back to `lockDevice()`. The auth stub counts `auth.signOutCalls`. guide.html's security note explains both.
- **Concurrent check-ins (Oct 2026):** measured on real Firebase, several door phones scanning at once failed with permission-denied and were kicked out (`sessionRevoked`, guest not checked in). Cause: handleScan wrote `scannedCount = old+1` from a `tx.get(eventRef)` read, and the rule (`scannedCount == resource.data.get('scannedCount',0)+1`) denies a stale value when another phone committed first. Fix in scan.html: no event read in the transaction, `tx.update(eventRef, { scannedCount: increment(1) })` (`increment` from `window._fsFns`; scan.html uses firebase-init.js, not the lite one). Safety net: on permission-denied, only for door-code devices (`usesSessionDoc`), `sessionStillValid()` reads the device's own `scanSessions/{uid}`; if it exists the transaction is retried up to 2 more times after 100-400 ms, otherwise (or when retries run out) `sessionRevoked()`; organizer/admin scans are not retried; `scanEpoch` is re-checked after every await. `firestore.rules` is unchanged (the rule evaluates the incremented result, so +1 passes and +2 still fails; guarded in the rules tests). sw.js `CACHE_NAME` v14.
- **Check-in by name (Oct 2026):** scan.html's "عرض الأسماء" list now searches (name any length; code only at 3+ chars or a `wd` prefix; 200 ms debounce, `onListSearchInput`) and registers: an unscanned row has a "تسجيل" button (`armListRow`) that opens one row in place (name, full code, "تأكيد الدخول" / "إلغاء", confirm ignored for the first 400 ms) and `checkInFromList(id)` calls the same `handleScan(id)` as a QR scan (result overlay, sound, VIP flag from the transaction; sets `lastScanned=null` and `unlockAudio()` first). Every row shows a small code tag (4 chars after `WD-`) so equal names differ; scanned rows show "✓ دخل" plus "HH:MM" only when this device did it (`localCheckinTimes`). Rendering reads the in-memory `guests` array (the saved copy only when it is empty), at most 60 rows (`LIST_MAX_ROWS`) with a note for the rest, one delegated click handler on `#offline-list-results`. `handleScan` now also marks a duplicate's guest as scanned in the local list/cache and re-renders after both outcomes. `resetListState()` (clears the open row and busy flag) runs with sessionRevoked / lockDevice / lockOrClose / resetScanState. List-only mode (event doc failed to load, `eventData` null) has no buttons and keeps "للقراءة فقط". A new query text clears the open row at once (not in the debounced render); a scan of a guest missing from the saved-copy fallback (`listFallback`, used only when `guests` is empty) updates the fallback only and never pushes into `guests`. No rules change, no extra reads, roster format untouched (so no VIP badge in the list). sw.js `CACHE_NAME` v15. Shipped as ONE commit so it can be reverted alone. - **Old Android compat (Oct 2026):** an old Android Chrome showed a tall camera box without the scan frame/line (no CSS `inset` / `aspect-ratio`) and read no QR codes. All html files now use `top:0; right:0; bottom:0; left:0` instead of `inset`, and scan.html's `#camera-wrapper` is a `::before{padding-top:100%}` square with the video absolutely positioned (index.html's `.cp-qr` uses `height:0; padding-top:100%`) — keep it that way (a static test in scan.spec.js fails on `inset:` / `aspect-ratio` in any html). Debug helpers on scan.html: `?event=ID&debug=1` shows a panel under the camera box (user agent, Chrome version, BarcodeDetector + formats, hasCamera, video size/readyState, started, decode-error count and last error, decodes), refreshed every second and console.logged; `&timing=1` shows the sign-in/write/total timing and now "تأخير النقرة" (click event to checkPin start). Finding: in Playwright the extra ~1.5 s between click and the scanner view is Playwright waiting for the splash overlay to stop covering the button (not a page problem; real input delay was 1-2 ms). Oldest-browser floor from the CSS/JS the pages use: flex `gap` (Chrome 84), `margin-inline`/`padding-inline` (87), optional chaining `?.` (80), `overflow-wrap:anywhere` (80); no `??`, `:is/:has`, dvh, structuredClone, replaceAll, `.at()`.
- **Scanner splash (Oct 2026):** scan.html's splash (design and animations untouched) now hides when window `load` has fired AND ≥800 ms passed since its script ran; an unconditional 2000 ms cap timer hides it regardless of load or the app script (was a fixed 2200 ms); fade 0.3 s, node removed 400 ms after hiding so its infinite animations stop. The hide script stays isolated, in the same place. `tests/scan.spec.js` measures the real hide time (≥ load, ≥800 ms, < 2.2 s).
- **Names list delta sync (Oct 2026):** door phones now see who entered on other phones without the owner's dashboard being open (the roster document is only rewritten while the dashboard is open). scan.html `syncEnteredGuests(force)`: ONE query `getDocs(query(guests, where('scannedAt','>',cursorISO)))` (single-field range, automatic index, no orderBy; null/absent scannedAt never match; scannedAt and cursor are ISO strings), raced against an 8 s timeout, OR-merged into `guests` (`scanned` never goes back to false; other phones' times shown as "✓ دخل HH:MM"; a guest admitted but missing from the roster is pushed, which also fixes the total; an open confirm card for that guest is cleared and shows "✓ دخل"). Runs when "عرض الأسماء" opens (first open or last sync older than 2 min) and on "تحديث القائمة" (which now re-reads the roster, 1 read, merges names with scanned = local OR roster (guests the delta added that are newer than the roster stay), then runs the delta; the full `getDocs(guests)` remains only when the roster document is confirmed missing; a failed or cache-served roster read keeps the old list and shows "تعذّر التحديث", no download. A refresh costs about 1 (roster) + admissions since the last sync + the 5-minute overlap + the lookups; the cursor never moves backwards, so with the dashboard closed it does NOT re-read every admission since the old roster; after the saved copy expires (3 h) or the page reloads, the new cursor is the later of the saved copy's `syncedAt` and the roster-derived one and the copy's entered flags are merged in (a copy without `syncedAt`, the old format, is the exception: rebuilt from the roster alone, so every admission since the roster is read once). The roster read has the same 8 s timeout as the sync. A tap during an automatic sync waits for it and then runs its own). **Cursor** = query start minus 5 minutes (overlap so a commit during the previous query is not missed); after a roster load it is `roster.updatedAt` minus 5 minutes (the roster can be hours old; epoch if missing), after the getDocs fallback now minus 5 minutes; stored in the saved copy as `syncedAt` (+ `syncedOn`); an old saved copy without `syncedAt` is reloaded once from the roster. Failure: old list kept, meta line "تعذّر التحديث — الأسماء من HH:MM", never the connection banner; permission-denied -> `sessionRevoked()` (no retry); terminated client reloads. **No auto-refresh timer on purpose:** it would multiply the reads of every open phone (estimate about 1k reads per phone for a 700-guest event with the open/refresh pattern). Un-checking a guest (dashboard) sets scannedAt null and is NOT propagated: a guest the owner un-checks later stays "entered" on phones that already saw them until the saved copy is rebuilt (accepted), and a guest who entered on this device and was deleted later by the owner stays as a ghost row/total until the saved copy is rebuilt (accepted). Clock-skew limit: the cursor is compared with scannedAt written by other phones' clocks, so a phone whose clock is more than 5 minutes behind can have its check-ins missed until the saved copy is rebuilt (3 hours) or the roster is newer. The list shows only unscanned guests on an empty search (cap 60 with "يوجد N ضيف آخر لم يدخل — اكتب للبحث"), a search shows everyone; meta "لم يدخل: N من M · آخر تحديث HH:MM" turns amber after 10 minutes. No rules change (one rules check added: a door session can run the range query, an unrelated user cannot). sw.js `CACHE_NAME` v16. Shipped as ONE commit; rollback = revert it.
